# Story v3.1-03 — `TerminalSessionService` + cache schema

**Sub-project:** v3.1 Real-time Terminal
**Status:** Ready
**Depends on:** v3.1-02 (`TerminalCommandPolicy`)
**Effort:** M (3–5 hours)
**Branch:** `story/v3.1-03-session-service`

## Story

Introduce the service responsible for spawning non-blocking command
processes, persisting their state to cache, and managing their lifecycle
(start, stop, replay, destroy, history). Service-only — no controller
wiring or broadcasting yet. Those land in stories 04 and 05.

## Acceptance Criteria

1. New class `App\Services\TerminalSessionService` with public methods:
   - `spawn(string $project, string $command, string $cwd): TerminalSession`
   - `stop(string $sessionId): bool`
   - `replay(string $sessionId): array`  // `{session, chunks[], status}`
   - `destroy(string $sessionId): void`
   - `history(string $project): array`   // last 50 entries
   - `pushHistory(string $project, string $command, ?int $exitCode = null): void`
   - `tick(string $sessionId): void`     // called by tick-loop in story 04
2. New value object `App\Support\TerminalSession` (read-only DTO with `sessionId, pid, project, command, cwd, startedAt, lastChunkAt, status, exitCode`).
3. Cache schema implemented exactly as design Section 5:
   - `hermes:term:active:{session_id}` — TTL 5 min, refreshed on every chunk write
   - `hermes:term:buffer:{session_id}` — TTL 5 min, list of chunk JSON, capped at 512 KB FIFO
   - `hermes:term:project:{project}` — TTL 5 min, current session id pointer
   - `hermes:term:history:{project}` — TTL 30 days, list of command JSON, capped at 50 FIFO
4. `spawn()` uses Symfony Process `start()` (non-blocking), sets process group via `Process::setOptions(['create_process_group' => true])` if available, and persists active key + initial `meta` chunk in buffer.
5. `stop()` sends SIGTERM, waits 5 seconds, then SIGKILL. Updates status to `exiting`. Returns true on success.
6. `tick($sessionId)` reads incremental stdout/stderr via `getIncrementalOutput()`/`getIncrementalErrorOutput()`, appends chunk to buffer, refreshes TTL on active key, updates `last_chunk_at`. Returns silently when nothing changed.
7. `replay()` fetches buffer + active metadata. Buffer chunks ordered by `ts` ascending.
8. `destroy()` removes both `active` and `buffer` keys (history is preserved).
9. Audit log written to `storage/logs/terminal-audit.log` on every `spawn()`: structured JSON line with `project`, `command`, `cwd`, `session_id`, `ip`, timestamp.
10. Unit tests in `tests/Unit/Services/TerminalSessionServiceTest.php` cover happy path: spawn → tick → replay → stop → destroy. Use `sleep 0.1; echo ok` for real spawn but mock cache to keep tests fast.
11. `./vendor/bin/pint` clean.

## Out of Scope (handled later)

- Broadcasting `TerminalOutput` events — done in tick-loop story (04)
- Idle watchdog (10 min) and hard cap (60 min) enforcement — also in tick-loop
- Orphan PID sweep — also in tick-loop
- Controller wiring — story 05

## Dev Notes

- Audit log channel: add a new entry in `config/logging.php`:
  ```php
  'terminal-audit' => [
      'driver' => 'single',
      'path' => storage_path('logs/terminal-audit.log'),
      'level' => 'info',
  ],
  ```
- Session id format: `{pid}-{Str::random(6)}`
- Status enum (string): `running` | `exiting` | `done`
- Cache driver: use the configured default (file or redis). Tests use `array` driver via `phpunit.xml`.
