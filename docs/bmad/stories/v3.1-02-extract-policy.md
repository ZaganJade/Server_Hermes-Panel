# Story v3.1-02 — Extract `TerminalCommandPolicy`

**Sub-project:** v3.1 Real-time Terminal
**Status:** Done
**Depends on:** —
**Effort:** S (1–2 hours)
**Branch:** `story/v3.1-02-extract-policy` (merged into `feature/v3.1-realtime-terminal`)

## Story

Move the command-allow logic out of `TerminalService` into a dedicated
`TerminalCommandPolicy` class. This splits security policy from process
execution, gives us a single place to evolve the blocklist, and makes
the rules unit-testable in isolation.

While extracting, **relax** chaining (`;`, `&&`, `||`, `|`) per the
design's option-B decision, and **tighten** patterns flagged by the
hardening rescan (MED-5 in `bmm-workflow-status.yaml`).

## Context

Current `TerminalService::execute()` mixes concerns: working-directory
management, `cd`/`clear`/`pwd` builtins, blocklist enforcement, and
process spawning. The blocklist is also incomplete:

- `cat` blocked but `tee`, `awk`, `sed`, `chmod`, `find` allowed
- `rm -rf` blocked but `rm --recursive --force` lets through
- `php`, `python`, `node` `-e` / `-c` bypass `wget`/`curl` block

This story keeps `TerminalService` for cwd/builtins and moves the
allow/deny decision to the new policy class.

## Acceptance Criteria

1. New class `App\Services\TerminalCommandPolicy` exists with public method `allow(string $command): bool` and `reason(string $command): ?string` (returns nullable rejection reason for UI display).
2. `TerminalService::execute()` calls `$policy->allow($command)` before deciding what to spawn. The two `containsCommandChaining()` and `containsDangerousPatterns()` private methods are removed.
3. Chaining operators (`;`, `&&`, `||`, `|`) are now allowed.
4. The following remain blocked (with explicit unit tests for each):
   - Command substitution: `$(...)`, backtick
   - Trailing `&` (background fork)
   - Newline / CR injection
   - Interactive bins: `vim`, `vi`, `nano`, `emacs`, `less`, `more`, `man`, `top`, `htop`, `ssh`, `scp`, `sudo`, `su`, `mysql`, `psql`
   - `rm` with both short (`-rf`) and long (`--recursive --force`) forms when target is `/`, `/etc`, `/home`, `/root`, `/var`, or `/usr`
   - `dd`, `mkfs`, `nc`, `ncat`
   - Output redirect `>/...` to FS root except `/tmp`, `/var/tmp`
   - Input redirect `</...` from FS sensitive except `/dev/null`, `/dev/zero`
   - `php -r`, `php -e`, `python -c`, `node -e` (eval-style code injection)
5. `tests/Unit/Services/TerminalCommandPolicyTest.php` covers every rule with positive and negative cases (≥30 assertions).
6. Existing terminal behavior at `/panel/api/terminal/execute` is preserved: same JSON response shape, same `cd`/`clear`/`pwd` builtin handling.
7. `./vendor/bin/pint` clean.
