# Story v3.1-05 — API contract + controller update

**Sub-project:** v3.1 Real-time Terminal
**Status:** Ready
**Depends on:** v3.1-03 (`TerminalSessionService`), v3.1-04 (tick-loop)
**Effort:** M (3–5 hours)
**Branch:** `story/v3.1-05-api-contract`

## Story

Wire the new session service through HTTP. Replace the old synchronous
`POST /panel/api/terminal/execute` with an async session-spawning
endpoint, keep a backward-compat sync path, add stop/replay/clear-history
endpoints, and lock down the broadcast channel auth.

## Acceptance Criteria

1. `routes/web.php` updated to expose:
   - `GET    /panel/api/terminal/state`
   - `POST   /panel/api/terminal/execute`         (async, throttle:30,1)
   - `POST   /panel/api/terminal/execute-sync`    (legacy sync, kept for trusted-network bypass mode)
   - `POST   /panel/api/terminal/{session}/stop`
   - `GET    /panel/api/terminal/{session}/replay`
   - `POST   /panel/api/terminal/reset`
   - `DELETE /panel/api/terminal/history`
2. `TerminalController` extended with `execute`, `executeSync`, `stop`, `replay`, `clearHistory` methods. `execute` returns 202 with `{session_id, started_at}`; 401 unauth; 422 if blocked by `TerminalCommandPolicy`; 409 if session already running for that project (with current session_id in body).
3. `executeSync` preserves prior behavior: returns `{output, error, cwd, exit_code, display}` synchronously. Fallback for trusted-network bypass mode where WS is unavailable.
4. `routes/channels.php` updated:
   ```php
   Broadcast::channel('terminal.{project}', function ($user, $project) {
       if (! config('panel.auth_enabled', true) && config('panel.dev_bypass', false)) {
           return false; // bypass mode → no real-time terminal
       }
       if (! session('panel_auth')) {
           return false;
       }
       return ['user' => 'panel', 'project' => $project];
   });
   ```
5. `BroadcastServiceProvider` is registered (Laravel 13 may default to lazy registration; ensure `routes/channels.php` is loaded).
6. Feature tests in `tests/Feature/Panel/TerminalApiTest.php` cover:
   - `/state` idle response
   - `/state` running response
   - `/execute` 401 when unauth
   - `/execute` returns session_id when authed
   - `/execute` 422 when project missing
   - `/execute` 422 when command blocked by policy
   - `/execute` 409 when session running for project
   - `/execute` rate-limited at 31st request
   - `/{session}/stop` invokes service stop
   - `/{session}/replay` returns buffered chunks
   - `DELETE /history` clears history
7. Feature tests in `tests/Feature/Panel/TerminalChannelAuthTest.php` cover:
   - `/broadcasting/auth` 403 in trusted-network bypass mode
   - `/broadcasting/auth` 403 without `panel_auth`
   - `/broadcasting/auth` 200 with valid session
8. OpenSpec capability spec created at `openspec/changes/realtime-terminal-v31/specs/realtime-terminal/spec.md` documenting all endpoints + the channel.
9. README "Real-time terminal" section expanded — endpoint table, channel name, error responses.
10. `./vendor/bin/pint` clean.

## Dev Notes

- Session id is opaque to client. URL parameter regex must allow `[A-Za-z0-9-]+`.
- `Broadcast::fake()` for feature tests. No Reverb required.
- For 409 conflict, payload shape: `{error: "Session already running", session_id: "..."}`. Client decides whether to wait, force-stop, or abort.
- `executeSync` continues to call existing `TerminalService::execute()` so behavior in trusted-network mode is unchanged. Document this clearly in code comments.

## Smoke Check

```bash
# Logged in (auth enabled):
curl -X POST http://127.0.0.1:8080/panel/api/terminal/execute \
     -H 'X-Panel-Password: changeme' \
     -H 'Content-Type: application/json' \
     -d '{"project":"desakta","command":"sleep 1; echo hi"}'
# expect 202 {session_id, started_at}

curl -X GET http://127.0.0.1:8080/panel/api/terminal/{session}/replay \
     -H 'X-Panel-Password: changeme'
# expect chunks
```
