## Acceptance Criteria

1. npm install: `uplot` (latest stable, ~30 KB).
2. New JS modules under `resources/js/monitoring/`:
   - `index.js` — Alpine factory `hermesMonitoring()` for full tab + `hermesHealthStrip()` for Dashboard partial
   - `snapshot-store.js` — singleton subscriber: connects to `monitoring.host` once (or polls `/snapshot` in bypass mode), fans out to subscribers
   - `charts.js` — uPlot factory + sparkline factory + editorial dark theme tokens
   - `series.js` — HTTP series fetcher with debounce + window-to-resolution mapping
3. `resources/js/app.js` registers factories:
   ```js
   import { hermesMonitoring, hermesHealthStrip } from "./monitoring";
   Alpine.data("hermesMonitoring", hermesMonitoring);
   Alpine.data("hermesHealthStrip", hermesHealthStrip);
   ```
4. New blade partial `resources/views/panel/_dashboard_health_strip.blade.php`:
   - 4 cards (CPU, Memori, Disk, Jaringan) in grid
   - Each shows current value + 60-point sparkline canvas
   - Card border turns copper on warning, rust on critical
   - Click → navigate to `/panel/monitoring#<metric>`
5. `resources/views/panel/dashboard.blade.php` includes the strip at top.
6. New full view `resources/views/panel/monitoring.blade.php`:
   - Header strip (4 sparklines bigger than Dashboard)
   - Window selector (5m / 15m / 1h / 6h / 24h)
   - Charts grid (CPU load, Memory + swap, Disk I/O, Network I/O, Disk usage per mount, TCP connections)
   - Services table with refresh button
   - Process top + Listening ports collapsible sections
   - Alerts log sticky bottom
7. Sidebar gets 6th tab `ζ Monitoring` (after `ε Projects`):
   - Glyph: `ζ` (zeta)
   - Route: `panel.monitoring`
   - Same hover + active state pattern as existing tabs
8. E2E test `tests/e2e/monitoring.spec.ts` (Playwright):
   - Open `/panel/dashboard`, assert 4 health-strip cards
   - Click CPU card, assert URL is `/panel/monitoring#cpu`
   - Assert charts grid + services table render
   - Switch window selector 15m → 1h, assert XHR to `/series` fires
   - Skip-when-unreachable wrapper (same pattern as v3.1 E2E)
9. README "VPS monitoring" section finalizes with:
   - Architecture overview paragraph
   - Configuration table (thresholds + service patterns)
   - Storage notes (`storage/monitoring.sqlite`, retention policy)
   - Upgrade notes (recreate container for new volume mounts)
10. `agents.md` section 15 update: v3.2 status from "backlog" to "DONE".
11. `docs/bmad/bmm-workflow-status.yaml` updates:
    - `phase_4_implementation.stories_completed += 8`

    - umbrella v3.2 status `active` → `done`
    - workflow_log: append `dev-story` entry for v3.2-08 + `sprint-close` entry
