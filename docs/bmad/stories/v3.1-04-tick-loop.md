# Story v3.1-04 — Tick-loop artisan command + supervisord entry

**Sub-project:** v3.1 Real-time Terminal
**Status:** Ready
**Depends on:** v3.1-03 (`TerminalSessionService`)
**Effort:** M (3–5 hours)
**Branch:** `story/v3.1-04-tick-loop`

## Story

Add the long-running tick-loop process that drives all active terminal
sessions: reads incremental output, broadcasts `TerminalOutput` events
via Reverb, enforces idle and hard-cap watchdogs, sweeps orphans on
boot, and exits gracefully on SIGTERM.

## Acceptance Criteria

1. New artisan command `App\Console\Commands\TerminalTickLoop` registered with signature `hermes:terminal-tick`.
2. Loop sleeps 100 ms between iterations and scans cache for keys matching `hermes:term:active:*`.
3. For each active session: call `TerminalSessionService::tick()`. When a new chunk is produced, dispatch `App\Events\TerminalOutput` event (defined in this story).
4. `TerminalOutput` implements `ShouldBroadcast`, broadcasts on `PrivateChannel("terminal.{$project}")`, `broadcastAs()` returns `terminal.output`, `broadcastWith()` returns `{session_id, ts, type, data, exit_code?}`.
5. Idle watchdog: when `now - last_chunk_at > 600s`, send SIGTERM and emit synthetic `exit` chunk with `exit_code: -1` and message `[idle timeout, killed after 10 min]`.
6. Hard cap: when `now - started_at > 3600s`, same as idle but message `[runtime cap, killed after 60 min]`.
7. On boot, sweep all `hermes:term:active:*` keys and validate PID with `posix_kill($pid, 0)`. Dead PIDs → emit synthetic `exit` chunk with `exit_code: -2` and message `[orphaned, panel restarted]`, then drop the active key.
8. SIGTERM trap (`pcntl_signal(SIGTERM, ...)`): for each active session emit synthetic `exit` chunk with code `-3` message `[shutdown]`, send SIGTERM to children, wait up to 2 s, exit gracefully with code 0.
9. Add `[program:terminal-tick]` to `docker/supervisord.conf` running as user `hermes`, autostart, autorestart, stdout/stderr to `/dev/stdout`/`/dev/stderr`.
10. Verify with manual test: spawn a `sleep 5; echo done` session via tinker (story 03 smoke check), observe Reverb-bound client receiving chunks in real time.
11. `./vendor/bin/pint` clean.

## Dev Notes

- Cache scan: PHP cache stores don't expose `keys()` natively. Pragmatic alternative: maintain a separate set key `hermes:term:active-set` (a serialized array) updated by `spawn`/`destroy`. The tick-loop iterates this set instead of scanning the underlying store.
- Use `pcntl_async_signals(true)` to make signal traps reliable.
- Log to a dedicated channel `terminal-tick` (single file, daily rotation OK) at `storage/logs/terminal-tick.log` for debugging.
