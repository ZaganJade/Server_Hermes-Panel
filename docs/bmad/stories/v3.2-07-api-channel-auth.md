# Story v3.2-07 — HTTP API + channel auth + OpenSpec

**Sub-project:** v3.2 VPS Monitoring
**Status:** Ready
**Depends on:** v3.2-05 (storage), v3.2-06 (tick-loop + events)
**Effort:** M (3–5 hours)

## Story

Expose the monitoring backend through HTTP and the Reverb channel.
Match the v3.1 pattern: auth gates async features, sync polls fall back
in trusted-network bypass mode, capability documented in OpenSpec.

## Acceptance Criteria

1. New `App\Http\Controllers\Panel\MonitoringController` with methods (per design Section 5):
   - `index()` — render `panel.monitoring` view
   - `snapshot()` — JSON of latest snapshot (or empty + error if none yet)
   - `series(Request)` — validates `metrics` array (required, max 20, max 128 chars each) + `window` enum; returns raw or 1m resolution per design rules
   - `services()`, `processes()`, `ports()` — pull discrete state from latest_snapshot.entries
   - `alerts()` — returns `{active: [...]}` from `ThresholdEvaluator::activeAlerts()`
   - `refreshServices()` — clears `hermes:monitoring:services:units` cache, returns `{success: true}`
2. Routes in `routes/web.php` under `panel/api/monitoring`:
   - `GET /panel/api/monitoring/snapshot`
   - `GET /panel/api/monitoring/series`
   - `GET /panel/api/monitoring/services`
   - `GET /panel/api/monitoring/processes`
   - `GET /panel/api/monitoring/ports`
   - `GET /panel/api/monitoring/alerts`
   - `POST /panel/api/monitoring/services/refresh`
   - `GET /panel/monitoring` (full tab, returns view)
3. Channel auth in `routes/channels.php`:
   ```php
   Broadcast::channel('monitoring.host', function ($user) {
       if (! config('panel.auth_enabled', true) && config('panel.dev_bypass', false)) {
           return false;
       }
       if (! session('panel_auth')) {
           return false;
       }
       return ['user' => 'panel'];
   });
   ```
4. Feature tests:
   - `tests/Feature/Panel/MonitoringApiTest.php`:
     - snapshot requires auth (401 unauth)
     - snapshot returns latest payload after tick-loop run
     - snapshot returns empty + error when no samples yet
     - series validates metrics array, rejects > 20 metrics
     - series returns raw resolution for ≤1h windows
     - series returns 1m resolution for >1h windows
     - services returns list from latest_snapshot
     - services/refresh clears cache key
   - `tests/Feature/Panel/MonitoringChannelAuthTest.php` (same pattern as TerminalChannelAuthTest):
     - Channel callback rejects in trusted-network bypass mode
     - Channel callback rejects without panel_auth session
     - Channel callback accepts with active session, returns presence data
5. OpenSpec capability spec at `openspec/changes/vps-monitoring-v32/specs/vps-monitoring/spec.md`:
   - All endpoints documented with scenarios
   - Channel auth scenarios
   - Threshold evaluator behavior scenarios
6. README "VPS monitoring" section gets API endpoint table + channel name + error responses (full content lands in story 08).
7. `./vendor/bin/pint` clean.

