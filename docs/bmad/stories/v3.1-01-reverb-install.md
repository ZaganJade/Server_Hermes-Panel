# Story v3.1-01 — Install Reverb + Broadcasting Config

**Sub-project:** v3.1 Real-time Terminal
**Status:** Ready
**Depends on:** —
**Effort:** S (1–2 hours)
**Branch:** `story/v3.1-01-reverb-install`

## Story

As the panel operator, I want Laravel Reverb installed and configured as
the broadcast driver, so that subsequent stories can publish events
through a real WebSocket server instead of relying on the supervisord
entry that is currently spawned without the package being present.

## Context

`docker/supervisord.conf` already starts `php artisan reverb:start --host=0.0.0.0 --port=8081`, but `composer.json` has no `laravel/reverb` dependency. The supervisord program currently fails on container boot — silently, because supervisord auto-restarts and the panel never depends on it. This story closes the gap.

## Acceptance Criteria

1. `composer require laravel/reverb` succeeds and the dependency is committed in `composer.json` and `composer.lock`.
2. `BROADCAST_CONNECTION=reverb` is added to `.env.example` together with the full `REVERB_APP_ID`, `REVERB_APP_KEY`, `REVERB_APP_SECRET`, `REVERB_HOST`, `REVERB_PORT`, `REVERB_SCHEME`, `REVERB_SERVER_HOST`, `REVERB_SERVER_PORT` keys with sensible defaults (placeholder strings for secrets, host `0.0.0.0`, port `8081`).
3. `VITE_REVERB_APP_KEY`, `VITE_REVERB_HOST`, `VITE_REVERB_PORT`, `VITE_REVERB_SCHEME` are added to `.env.example` so Vite can expose them at build time.
4. `php artisan reverb:start --host=0.0.0.0 --port=8081` runs cleanly in the container; supervisord shows the program as RUNNING for at least 30 seconds without restart.
5. A throwaway broadcast sanity check (e.g. via `php artisan tinker` dispatching a `TestEvent` on a public channel) is received by an Echo-bound client (raw HTML test page is acceptable; full frontend wiring lands in stories 06–07).
6. README "Real-time terminal" section gets a stub paragraph explaining that Reverb runs at port 8081 internally and is reverse-proxied through `/app`.

## Dev Notes

- Reverb defaults to `0.0.0.0:8080` after install. Override via `REVERB_PORT=8081` in `.env.example` to avoid colliding with nginx in the container.
- The container nginx proxy `/app` block was already updated to forward to `127.0.0.1:8081` in earlier hardening work — verify no regression.
- For the public-domain deployment (shape D) the public WS URL is `wss://panel.example.com/app`, so `VITE_REVERB_PORT=443` and `VITE_REVERB_SCHEME=https` in production. Document this in `.env.example` comments.

## Smoke Check

1. `docker compose up -d --build`
2. `docker compose logs hermes-panel | grep reverb` — RUNNING state
3. `docker compose exec hermes-panel php artisan tinker`
4. `>>> broadcast(new \\Illuminate\\Broadcasting\\BroadcastEvent(...))` (or any quick test event on a public channel)
5. Browser-side Echo client subscribed to that channel receives the payload
