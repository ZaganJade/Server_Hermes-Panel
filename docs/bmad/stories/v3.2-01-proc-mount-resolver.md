# Story v3.2-01 — Mount /proc, /sys + ProcResolver

**Sub-project:** v3.2 VPS Monitoring
**Status:** Ready
**Depends on:** —
**Effort:** S (1–2 hours)

## Story

Add read-only volume mounts for `/proc` and `/sys` to the container, and
introduce `ProcResolver` so all subsequent readers share a single
abstraction over "where is /proc on this system" — autodetect picks
`/host/proc` inside the container and `/proc` everywhere else.

## Acceptance Criteria

1. `docker-compose.yml` adds two read-only mounts:
   - `/proc:/host/proc:ro`
   - `/sys:/host/sys:ro`
2. New class `App\Services\Monitoring\ProcResolver` with:
   - `static autodetect(): self` — picks `/host/proc` if dir exists, else `/proc`; same logic for `/host/sys` ↔ `/sys`
   - `proc(string $path): string` — joins resolved root with relative path
   - `sys(string $path): string` — same for /sys
   - `readFile(string $procPath): string` — reads + throws on failure with informative message
3. Bound as singleton in `AppServiceProvider::register()` via `ProcResolver::autodetect()`.
4. Unit test `tests/Unit/Services/Monitoring/ProcResolverTest.php`:
   - autodetect picks `/host/proc` when path exists, else `/proc`
   - autodetect picks `/host/sys` independently from /proc
   - `readFile` returns content for valid path
   - `readFile` throws `\RuntimeException` with full path in message when missing
   - `proc()` joins paths correctly with leading slash
5. README "VPS monitoring" section gets a stub paragraph (full content lands in story 08).
6. `./vendor/bin/pint` clean on touched files.
