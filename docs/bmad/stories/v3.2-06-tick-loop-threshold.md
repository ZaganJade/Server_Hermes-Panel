# Story v3.2-06 — MonitoringTickLoop + ThresholdEvaluator + supervisord

**Sub-project:** v3.2 VPS Monitoring
**Status:** Ready
**Depends on:** v3.2-03 (network/disk readers), v3.2-04 (process/service readers), v3.2-05 (storage)
**Effort:** M (3–5 hours)

## Story

Tie everything together: long-running artisan command samples every 5
seconds, evaluates thresholds with hysteresis, persists to SQLite, and
broadcasts via Reverb on `monitoring.host` private channel.

## Acceptance Criteria

1. `App\Services\Monitoring\ThresholdEvaluator`:
   - Constructor accepts CacheRepository + Dispatcher
   - `evaluate(Snapshot $snapshot): array` — returns alerts produced this tick
   - Default rules from `config('panel.monitoring.thresholds')`
   - Hysteresis: state cached at `hermes:monitoring:threshold:{rule_id}`, TTL 600s
   - Sustained-time rule (cpu_load): tracks first-cross timestamp, fires only after `sustained_seconds`
   - `service_down` rule: only fires for units present in `hermes:monitoring:expected_services` cache (units seen `active` in last 5 minutes)
   - Emits `MonitoringAlert` event on level transitions only (ok→warn, warn→crit, crit→ok, etc.)
   - `activeAlerts(): array` — current non-ok rule states for HTTP /alerts
2. `App\Events\MonitoringAlert` (in-process event, not broadcast):
   ```php
   public function __construct(
       public readonly string $ruleId,
       public readonly string $level,
       public readonly string $message,
       public readonly mixed $currentValue,
       public readonly int $ts,
   ) {}
   ```
3. `App\Events\MonitoringSnapshot` (broadcast event):
   - Implements `ShouldBroadcast`
   - `broadcastOn()` returns `[new PrivateChannel('monitoring.host')]`
   - `broadcastAs(): string` returns `'monitoring.snapshot'`
   - `broadcastWith()` returns `{ts, entries, alerts, errors}`
4. `App\Console\Commands\MonitoringTickLoop`:
   - Signature `hermes:monitoring-tick {--max-iterations=0} {--sleep=5}`
   - Calls `MetricStorage::bootstrap()` once on handle entry
   - Loop: sample → evaluate thresholds → record sample → broadcast event
   - Every 12th iteration: aggregate previous minute, prune retention windows
   - Drift correction: `usleep(max(0, sleep_seconds - elapsed))` per iteration
   - SIGTERM + SIGINT trap (pcntl) for graceful shutdown; degrades on Windows hosts
   - Catches per-iteration exceptions; logs to `monitoring-tick` channel; loop continues
5. Default thresholds in `config/panel.php`:
   ```php
   'monitoring' => [
       'thresholds' => [
           ['id' => 'cpu_load', 'metric' => 'cpu.loadavg.1m', 'warning_factor_per_core' => 1.5, 'critical_factor_per_core' => 2.0, 'sustained_seconds' => 60],
           ['id' => 'mem_used', 'metric' => 'mem.used_kb', 'warning_pct' => 90, 'critical_pct' => 95],
           ['id' => 'disk_used', 'metric' => 'disk.*.used_pct', 'warning' => 90, 'critical' => 95],
           ['id' => 'service_down', 'metric' => 'services', 'critical_when' => 'expected_active_but_not'],
       ],
   ],
   ```
6. Supervisord entry in `docker/supervisord.conf`:
   ```ini
   [program:monitoring-tick]
   command=php artisan hermes:monitoring-tick
   directory=/var/www/html
   user=hermes
   group=hermes
   autostart=true
   autorestart=true
   startsecs=2
   stopsignal=TERM
   stopwaitsecs=10
   stdout_logfile=/dev/stdout
   stderr_logfile=/dev/stderr
   ```
7. New log channel `monitoring-tick` in `config/logging.php` (single driver, info level).
8. Tests:
   - `tests/Unit/Services/Monitoring/ThresholdEvaluatorTest.php` — first cross emits, no spurious re-fire, transition warn↔crit, recovery emits clear, sustained-time rule, cache state survives between calls
   - `tests/Feature/Console/MonitoringTickLoopTest.php` — `--max-iterations=2` exits 0; Event::fake catches MonitoringSnapshot after 1 iteration; samples_1m has rows after 12 iterations; reader-failure isolated with errors[] populated
9. `./vendor/bin/pint` clean.
